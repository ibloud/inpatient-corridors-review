The production handoff

Ink source → compiled story data → JavaScript runtime → browser UI

Ink is the writer-facing narrative language; Inky is the authoring/preview environment; inkjs can run compiled Ink story data in a web context. The separation lets writers work on narrative while the browser layer handles presentation. Ink's official web tutorial describes the same general source-to-web workflow, and inkjs documents the browser runtime pattern.

One important boundary

The source-only Ink/music pilot is deliberately kept separate from the playable Yellow Door implementation. A story source is not a compiled release; a track brief is not an implemented narrator/audio track; and a streaming link is not rights clearance.

Start small

  • Map one branching story before changing it.
  • Make one controlled narrative revision.
  • Play the affected path and a neighboring path.
  • Build a small original Ink story with state, consequence, convergence, and two endings.
  • Record accessibility, QA, and provenance observations.
