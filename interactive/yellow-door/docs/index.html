Try the Ink + Shopify example

At the end of the story, an optional page offers one product from Ren’s official store and one from The Skinner Brothers’ official store. Each “Add 1” button opens that artist’s Shopify cart in a new tab. Buying is optional and does not affect the story. This public-link example does not access either store’s administration or live inventory.

On the artist’s Shopify side

  1. Have your store administrator confirm the selected product and variant, its price, stock, shipping markets and returns policy. The product must be available through your Online Store and accessible to customers.
  2. Confirm the numeric variant ID, rather than the product ID. Your developer can inspect your public product URL with .js appended and locate the matching entry under variants. This example uses one default variant per product; clothing or other choices need an explicit variant selector.
  3. No app installation, API token or theme change is needed for this permalink example. Test the corresponding “Add 1” link in a fresh browser session: it should open your own cart with the right item and quantity. Check your theme’s existing-cart behavior and test desktop, mobile, shipping regions and sold-out behavior. Only your team should authorize and complete a test order.
  4. For an official collaboration, approve product selection, wording and any artwork separately. A working public cart link does not imply artist approval or an affiliate arrangement.

On the Yellow Door side

  1. Edit artistProducts in interactive/yellow-door/docs/app.js: set each artist, title, store domain, product handle and numeric variant ID. Keep credentials out of the repository.
  2. continueStory() detects an Ink ending with no remaining choices and offers the optional music page. Clicking it runs renderPromo(), which renders the two cards via createArtistProducts(). Ink does not submit orders or share story variables with either store.
  3. Each button follows https://STORE/cart/VARIANT:1?storefront=true. The store creates the cart after the visitor clicks; Shopify handles checkout, payment and fulfillment. Two independent stores mean two separate checkouts.
  4. Update this table when products change; retain the product-details fallback. Bump the script version in this page and deploy. Verify preview → correct merchant cart, and story ending → optional page → both cards.

Later, with merchant authorization: use each store’s Storefront API to retrieve current product data and create that store’s cart. Browser code may use a designated public Storefront token; Admin credentials and private tokens must stay on a server. That API connection is not part of this example.

Reference: Shopify’s cart permalink instructions ↗. No payment details, email, story scores or tracking parameters are added to these links.
